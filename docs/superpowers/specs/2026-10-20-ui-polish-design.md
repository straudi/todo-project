## 목적과 범위

**사람이 말한 것**

- 할 일 카드 앱의 UI/UX 개선 방향을 기획한다. 기존 기능은 그대로 둔다. 와이어프레임과 디자인 계획부터 만든다.
- 목적은 **보기 좋게 다듬기**다. 머리 영역, 시각적 위계, 전체 완성도를 다룬다.
- 지금 디자인에 얽매이지 않고 **분위기를 새로 정한다**.
- 브레인스토밍 중에 고른 것: 시각 방향 **C. 또렷한 편집형**, 머리 영역 **큰 제목 + 요약 줄**, 구현 방식 **A. 변수와 CSS 중심 갈아입히기**, 만들기 창 제목 **넣음**. 섹션 ① ~ ⑤는 모두 승인했다.

**AI의 가정 (사람이 고치지 않음)**

- PRD "이번에 만들지 않을 기능"은 이번에도 넣지 않는다.
- 어두운 화면과 웹 글꼴 내려받기는 지금처럼 만들지 않는다 (DESIGN.md "정한 방향").

**성공 기준**

- 섹션 ① ~ ⑤의 모양이 화면에 들어간다.
- 기능 F-01 ~ F-08과 SCREEN-SPEC의 동작, 문구, 버튼 순서가 하나도 바뀌지 않는다. 기존 자동 테스트가 모두 그대로 통과한다.
- 글자 대비는 모두 4.5:1 이상이다 (누를 수 없는 버튼은 지금처럼 예외).

## 바꾸지 않는 것

- 기능, 동작, 안내 문구의 문장, 버튼 순서, 칸 순서, 칸 안 순서
- 만들기 창: 취소 버튼으로만 닫힘, 처리 중 두 버튼 막힘, 실패하면 입력 유지 ([D-008](../../../DECISIONS.md))
- 처리 중에는 버튼을 막기만 하고 다른 처리 중 표시는 넣지 않음 (SCREEN-SPEC "대안과 결정")
- 768px 미만에서 세 칸을 세로로 쌓음, 휴대폰은 상태 메뉴만 씀 ([D-007](../../../DECISIONS.md))
- 끄는 동안 원래 카드는 투명도 50% (`e2e/tests/status.spec.ts`가 확인함)
- 글꼴은 기기 기본 글꼴, 아이콘은 lucide-react ([D-014](../../../DECISIONS.md)), 새로 설치하는 도구 없음 ([D-012](../../../DECISIONS.md))
- 앱 안 AI 기능 없음 ([D-001](../../../DECISIONS.md))

- 끄는 중: 원래 카드는 투명도 50%, 마우스가 올라간 칸은 먹색 3px 외곽선을 6px 띄워 그린다.

## 구현 방식 (A)

색·모양 값은 이미 `frontend/src/index.css`의 `:root` 변수와 `[data-status]` 칸별 변수에 모여 있으므로, 변수를 바꾸고 규칙을 손보는 방식으로 갈아입힌다. 새 도구는 없다.

| 파일 | 바꿀 내용 |

**요약 줄의 동작**

- 내용: "할 일 N", "진행 중 N", "완료 N" 태그 세 개와 "· 모두 N장". 숫자는 칸 머리의 개수와 같은 값이다.
- 카드를 만들거나, 옮기거나, 지우면 칸 머리 개수와 함께 바로 바뀐다 (서버가 성공을 알린 뒤).
- 처음 열 때 목록을 받지 못하면 숨긴다. 앱 제목과 "새 카드"는 보인다.
- 누를 수 없는 글자다. 화면 읽기 도구가 읽을 수 있게 "상태별 카드 개수" 같은 이름을 붙인다.

**머리 영역의 구조**

- 지금 칸 이름은 `h2`, 카드 제목은 `h3`이다. 앱 제목을 `h1`으로 두면 제목 단계가 맞는다.

## 확인 방법

1. **기존 자동 테스트:** `backend`의 pytest와 `e2e`의 Playwright 테스트 전부가 고치지 않은 채로 통과해야 한다. 모양 값을 직접 확인하는 테스트는 투명도 0.5 하나이며 바꾸지 않는다. 기존 테스트가 쓰는 이름(`새 카드` 버튼, 칸 이름 heading, 상태 표시 글자)은 바뀌지 않는다. 카드 제목이 "할 일 카드"인 테스트(T-20)는 칸 안에서만 찾으므로 앱 제목과 겹치지 않는다.
2. **새 자동 테스트 (Playwright):**
   - 앱 제목 "할 일 카드"가 보인다.
   - 요약 줄의 세 숫자와 "모두 N장"이 칸별 카드 수와 같다. 만들기, 옮기기, 지우기 뒤에도 같다.
   - 목록을 받지 못하면 요약 줄이 보이지 않는다.
   - 만들기 창에 제목 "새 카드"가 보인다.
3. **화면 확인:** 컴퓨터 너비와 375px 너비에서 섹션 ① ~ ④와 같은지 화면을 찍어 본다. 키보드로 Tab을 눌러 포커스 외곽선이 보이는지 본다. 이 확인을 누가 어떤 방법으로 할지는 **미정**이다 ("미정" 절).
4. **대비:** 실제로 들어간 CSS 값으로 대비를 다시 계산해, 위 표와 같은지 본다.
